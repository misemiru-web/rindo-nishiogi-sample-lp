# りんどう 営業用サンプルLP 要件定義書（12セクション・本実装品質想定）

更新日: 2026-09-28  
文書種別: 営業提案用サンプルLP 要件定義 / 12セクション本実装品質想定  
対象工程: 12セクション再設計、画像選定・編集、Next.js / React / CSS実装、GitHub Pages公開

## 1. 文書の目的

本書は、西荻窪の飲食店「りんどう」の営業提案用サンプルLPについて、**正式納品する本実装と同等の情報設計・デザイン・実装品質**を想定し、目的、対象ユーザー、情報の扱い、12セクション構成、機能、素材、技術条件、完成基準を定義する。後続の画像選定・編集、デザイン調整、Next.js / React / CSS実装は本書を基準に進め、店舗固有情報を推測で補完しない。

公開環境は引き続き営業提案用サンプルとして扱い、GitHub Pages・`noindex,nofollow`・画面上のサンプル表記によって公式サイトとの誤認を避ける。一方、ページ構成は4時間以内の無料サンプル制約ではなく、**正式契約後にそのまま拡張・納品できる完成形**を想定する。したがって、料理、酒、季節性、コース、店内、ランチ、初回来店時の不安解消、アクセスまでを独立した役割として設計する。

最優先成果は、料理と酒に関心があるユーザーが「りんどうでどのような時間を過ごせるか」を理解し、最終的に食べログのディナー予約へ迷わず進める状態を作ることである。30〜50代・2〜4名利用は公開情報から確定した店舗ターゲットではなく、情報優先順位を決めるための営業仮説として扱う。

## 3. 情報源と優先順位

### 3.1 優先順位

| 優先度 | 情報源 | 扱い |
|---|---|---|
| A | 店主との直接確認、正式な支給資料 | 公開情報の最終的な正本 |
| A | 店舗公式Instagram | 店舗の雰囲気、料理、営業告知、写真の主要根拠 |
| B | 食べログの店舗公式掲載情報 | メニュー、コース、住所、営業時間、設備情報の仮根拠 |
| B | Googleマップ | 所在地と経路リンクの補助。第三者写真は使用しない |
| C | 第三者口コミ・紹介記事 | 構成検討の参考に限定し、店舗事実として掲載しない |

### 3.2 情報区分

**確認済み事実**

- 店舗名は「りんどう」。
- 西荻窪の飲食店で、公式Instagramは `rindo.nishiogi`。
- 添付された店舗写真とロゴは、営業提案用サンプルへの使用許可済み。
- LPはディナー予約を主目的とする1ページ構成。
- 主CTAは食べログ予約。
- デザイン方向は上質な和モダン。

**公開情報を基にした仮情報**

- 所在地: 東京都杉並区西荻北3-9-13。
- アクセス: 西荻窪駅北口から徒歩4分。
- 営業時間: 火曜日を除く11:30〜14:00、18:00〜22:00。
- 席数: 25席。カウンター3席、テーブル22席。
- 全席禁煙、個室なし、貸切相談可。
- ディナー予算の目安: 6,000〜7,999円。
- 炭焼き、一品料理、ナチュラルワイン、日本酒、焼酎などを提供。

これらは食べログの「店舗関係者によって公開」と表示される掲載内容を基にしており、サンプル提出前に店舗確認する。食べログの料理メニューは掲載上の更新日が2024年1月30日であるため、料理名・価格は**代表例の候補**としてのみ使用し、現行メニューとして断定しない。コースページに掲載されている「お料理10品2時間飲み放題付パーティープラン 5,500円」等も、正式公開前に店舗へ現行条件を確認する。

**未確認事項**

- 現在のランチメニューと、中華そばを「りんどう」で継続提供しているか。
- 2026年9月時点での正確な営業時間、ラストオーダー、臨時営業・休業。
- 現在有効なコース名、品数、料金、飲み放題時間。
- 貸切可能人数と最低利用条件。
- 予約用電話番号と店舗直通番号の使い分け。
- ランチ・ディナーそれぞれの支払方法とカード利用条件。
- 食物アレルギー、子ども連れ、ベビーカー対応に関する現行条件。

### 3.3 情報が矛盾する場合

- 店舗からの直接回答を最優先する。
- 次に、投稿日・更新日が新しい公式Instagramを優先する。
- 食べログは店舗公式掲載であっても、公開前の確認対象とする。
- 確認できない料金・営業時間・予約条件は断定せず、食べログまたはInstagramへの案内に置き換える。
- 古いInstagram投稿にあるパーティープラン料金をそのまま掲載しない。

## 4. 目的と成功条件

### 4.1 主目的

営業提案用サンプルの閲覧者が「料理と酒を落ち着いて楽しめる、西荻窪の店」と理解し、正式サイト化した場合に食べログのディナー予約へ自然に進める導線を確認できること。サンプル公開自体を店舗の公式な集客・商取引サイトとして運用しない。

### 4.2 副目的

- 店舗の料理、酒、店内の雰囲気を一貫したブランド体験として伝える。
- 少人数利用に加え、会食、コース、貸切相談が可能であることを補足する。
- 営業時間や季節メニューの最新情報を公式Instagramで確認できるようにする。
- 所在地と駅からの距離を分かりやすく示し、来店時の不安を減らす。

### 4.3 成功条件

**受入条件**

- ファーストビュー内に、店舗名、「西荻窪」、料理と酒の店であること、主CTAが存在する。
- Mobileで予約CTAが常に見つけやすく、固定CTAが本文や他の操作要素を隠さない。
- メニューを見たユーザーが、価格や内容が変動し得ることを誤解しない。
- 店舗情報・アクセスがページ内で明確に発見できる。
- 写真の魅力と情報の読みやすさが両立し、営業用サンプルとして店舗へ提案できる品質に達している。

**UX上の目標値（営業仮説）**

- 初見で3秒程度を目安に、店舗名、地域、料理と酒の店であること、予約導線を理解できる構成を目指す。
- 店舗情報・アクセスは1分以内を目安に確認できる情報量・階層を目指す。

上記の時間はユーザーテストで実測した確定値ではなく、デザイン評価の目安として扱う。

### 4.4 計測

営業用サンプル段階ではアクセス解析、広告タグ、コンバージョン計測を導入しない。正式契約後に、店舗の同意を得て食べログ予約リンクのクリック計測などを検討する。

## 5. 対象ユーザー

### 5.1 主対象（営業仮説）

以下は店舗から確認済みの顧客属性ではなく、公開情報と店舗表現を基に、営業サンプルの情報優先順位を決めるために置く仮説である。正式制作時は店舗ヒアリングや実データで更新する。

- 主に30〜50代を想定するが、年齢を限定する表現は画面上に出さない。
- 西荻窪周辺または中央線沿線で、個人店、旬の料理、ナチュラルワイン、日本酒など、料理と酒に関心がある。
- 2〜4名程度での夕食、デート、友人との食事、少人数会食を検討している。
- 店内の雰囲気、価格帯、駅からの距離を確認してから予約したい。

### 5.2 副対象

- 飲み放題付きコースや貸切を探しているグループ幹事。
- ランチ営業の有無を調べている近隣客。
- Instagram投稿を見て、店舗情報や予約方法を確認したいユーザー。

### 5.3 想定ニーズ

- どのような料理と酒が楽しめるか。
- 落ち着いて食事ができる店内か。
- 予算はいくら程度か。
- 予約可能か、どこから予約するか。
- 西荻窪駅からどの程度離れているか。
- コースやグループ利用に対応しているか。

## 6. ユーザー導線

### 6.1 主導線

1. Heroで料理写真、店舗名、「西荻窪」、料理と酒の店であること、予約導線を理解する。
2. Conceptで、りんどうが「料理と酒を落ち着いて楽しむ店」であることを短く理解する。
3. FoodとMenu Highlightsで、料理の幅と代表例を具体的にイメージする。
4. Seasonalで、固定メニューだけではない仕入れ・季節による変化を理解する。
5. Drinksで、料理と合わせてワイン、日本酒、焼酎などを楽しめることを理解する。
6. Course & Groupで、会食・グループ利用の選択肢を確認する。
7. Spaceで、席・内装・過ごし方をイメージする。
8. Lunchで昼営業の存在と最新情報の確認先を把握する。
9. First Visitで、予約条件・支払・子ども連れ等の初回来店時の疑問を解消する。
10. Accessで場所・営業時間・定休日を確認する。
11. Final Reservation CTAで行動を予約へ集中させる。

### 6.2 補助導線

- 当日の営業や季節メニューを知りたい → 公式Instagram。
- 場所を確認したい → Googleマップ。
- コース詳細や空席を確認したい → 食べログ。
- 電話で相談したい → 店舗確認済みの電話番号。

### 6.3 CTA配置

- Desktopヘッダー右端。
- Hero本文末尾。
- Menu HighlightsまたはDrinksセクション末尾の軽い導線。
- Course & Groupセクション末尾。
- Access内の店舗情報リンク。
- Final Reservation CTA。
- Mobile画面下部の固定バー。

主CTAの文言は「食べログで予約」に統一する。文脈に応じて補助説明として「空席とコースを確認できます」を添えてよい。Instagram、Googleマップ、電話は主CTAと同じ視覚強度にしない。

## 7. ページ構成

Global HeaderとFooterはサイト共通UIとして扱い、以下の12項目をコンテンツセクションとして定義する。

### 7.0 Global Header

**目的:** 店舗名の認知、主要セクションへの移動、予約導線の確保。

**掲載要素:** 正式ロゴ、店名、主要アンカーリンク、予約CTA、Mobileメニュー。

### 7.1 Section 01 — Hero

**目的:** 初回画面だけで「りんどう / 西荻窪 / お酒と料理 / 予約できる店」を理解させる。

**掲載要素:** 料理集合写真、ロゴまたは店名、「西荻窪 / お酒と料理」等の短い業態ラベル、H1、短い紹介文、食べログ予約CTA、営業提案用サンプル表記。

**仮コピー:** 「西荻窪、お酒と料理を楽しむ夜。」

「炭火」は公開情報上確認できる代表要素だが、店舗の唯一のブランド核として直接確認済みではないため、Heroの主コピーでは固定しない。

### 7.2 Section 02 — Concept / りんどうについて

**目的:** 業態名だけでは伝わらない店の価値を短く言語化する。

**掲載要素:** 料理と酒を楽しむ店であること、個人店らしい温度、白木を基調とした落ち着いた空間、少人数でゆっくり食事を楽しむ利用イメージ。未確認の料理人経歴・生産者ストーリー・契約農家等は記載しない。

### 7.3 Section 03 — Food / 料理

**目的:** 料理写真を主役にし、ジャンル名ではなく「りんどうの料理の幅」と手仕事感を伝える。

**掲載要素:** 料理集合または主料理写真、短い料理説明。「炭焼き」「魚料理」「一品料理」等は公開情報に基づく代表カテゴリーとして使用できる。

**方針:** 料理をカード一覧化しすぎず、大きな写真と短文で感情的な来店動機を作る。

### 7.4 Section 04 — Menu Highlights / 代表料理

**目的:** Foodで生まれた興味を、具体的な料理名へ接続する。

**掲載候補:** 食べログの店舗関係者公開メニューに掲載されている「レアアジフライ」「A5黒毛和牛のたたき」「〆鯖とフルーツトマト」「自家製ハムとトンナート」「パスタ類」等から、写真素材と整合する3〜5品を選定する。

**重要:** 食べログ料理メニューの掲載更新日は2024年1月30日であるため、料理名・価格は現行提供を店舗確認してから正式掲載する。価格は確認が取れるまで原則非表示とし、「内容は仕入れ等により変わります」と注記する。

### 7.5 Section 05 — Seasonal / 仕入れで変わる一皿

**目的:** 固定メニュー一覧ではなく、季節・仕入れによって内容が変わる店の楽しみを表現する。

**掲載要素:** 季節感のある料理写真2〜3枚、短いコピー、最新内容を確認するInstagram導線。

**根拠の扱い:** 食べログのコース説明にも「料理は仕入れによって多少変わる」と掲載されている。具体的な産地、生産者、入荷頻度は店舗確認なしに記載しない。

### 7.6 Section 06 — Drinks / 酒

**目的:** 「料理だけの店」ではなく、酒と一緒に過ごす夜の魅力を独立して伝える。

**掲載要素:** ナチュラルワインのボトル集合、グラス＋料理、日本酒・焼酎等のカテゴリ説明。公式Instagram・食べログ掲載で確認できる範囲に留める。

**CTA:** 「ドリンク・最新情報を見る」→食べログまたはInstagram。予約CTAより弱くする。

### 7.7 Section 07 — Course & Group / コース・グループ利用

**目的:** 通常の少人数利用に加え、会食・グループ・貸切相談の選択肢を示す。

**掲載要素:** 食べログに掲載される現行候補として「お料理10品2時間飲み放題付パーティープラン」を参照できるが、料金・品数・飲み放題時間・現金条件・貸切人数は正式公開前に店舗確認する。

**CTA:** 「コース・空席を食べログで確認する」。

### 7.8 Section 08 — Space / 店内・利用シーン

**目的:** 初回来店時の心理的不安を減らし、空間の明るさ、席の距離感、夜の落ち着きを伝える。

**掲載要素:** 店内広角、窓側、テーブル席、夜の店内写真。確認済みの場合のみ席数・禁煙等を補足する。

**禁止:** 個室があるように見せる表現、実際より広く見せる過度な広角補正、人物の生成追加。

### 7.9 Section 09 — Lunch / 昼のりんどう

**目的:** ディナー主軸を崩さず、昼営業という別の来店入口を補足する。

**掲載要素:** 昼営業時間、ランチの代表写真1〜2枚、最新内容を確認するInstagramまたは食べログ導線。

**注意:** 食べログにはランチメニューが掲載されているが掲載更新日は2024年1月30日。中華そばを含む具体メニューは現行提供を確認してから表示する。ランチ予約不可・ランチ現金のみという掲載情報も正式公開前に再確認する。

### 7.10 Section 10 — First Visit / 初めての方へ

**目的:** 予約直前の不安や認識違いを減らす。

**掲載候補:** ディナー最低2ドリンク、食事のみ利用の扱い、ランチ予約、支払方法、全席禁煙、子ども・ベビーカー、貸切相談等。食べログ店舗関係者掲載情報を仮根拠とし、画面表示する項目は店舗確認済みのものだけに限定する。

**UI:** FAQカード乱用ではなく、`dl`または必要最小限の`details/summary`で整理する。

### 7.11 Section 11 — Access / 店舗情報・アクセス

**目的:** 来店判断に必要な事実を正確かつ迷わず確認できるようにする。

**掲載要素:** 店名、住所、駅からの徒歩分数、営業時間、定休日、確認済みの設備情報、現在の外観写真、Googleマップ、食べログ店舗情報。

**公開情報上の仮値:** 東京都杉並区西荻北3-9-13、西荻窪駅北口から徒歩4分、火曜定休、昼11:30〜14:00（L.O.13:30）、夜18:00〜22:00（L.O.21:00）。正式公開前に店舗確認する。

### 7.12 Section 12 — Final Reservation CTA

**目的:** ページを読み終えたユーザーの行動を食べログ予約へ集中させる。

**掲載要素:** 短い予約コピー、食べログ予約CTA、Instagramリンク、確認済みの場合のみ電話リンク。営業提案用サンプルであることも補足する。

### 7.13 Footer

**掲載要素:** ロゴ、店名、住所、Instagram、食べログ、営業提案用サンプル表記、著作権表記。

**方針:** 12セクションをすべて本実装品質で設計する。制作時間を理由にFood・Drinks・Course・First Visit等を削る前提にはしない。ただし、店舗確認できない事実は表示せず、外部の最新情報へ誘導する。

## 8. コンテンツ要件

### 8.1 コピー

- 文章は簡潔で、店舗の魅力と来店判断に必要な内容へ絞る。
- 「絶品」「最高級」「地域一番」など根拠のない最上級表現を使わない。
- 店主の経歴、食材の産地、仕入れ先、製法を推測しない。
- 料理や酒の内容が変わる場合は「内容は仕入れにより変わります」と明記する。
- 営業時間や予約条件は、最新情報の確認先を明確にする。

### 8.2 メニュー

- 料理、ドリンク、コースは「全量転載」ではなく、ページ上の役割に必要な代表例だけを掲載する。
- Menu Highlightsは3〜5品程度を基本とし、写真素材と公開メニュー名が一致するものを優先する。
- 食べログ料理メニューの掲載更新日が2024年1月30日であることを踏まえ、料理名・価格は店舗確認後に確定する。
- 価格は確認前には原則非表示。表示する場合もHTMLテキストとし画像へ焼き込まない。
- 食べログから大量のメニュー文面・写真を転載しない。
- 詳細メニュー、空席、コース条件は食べログへ誘導する。
- ドリンクは銘柄リストを固定化せず、「ナチュラルワイン / 日本酒 / 焼酎」等のカテゴリと写真を中心にする。

### 8.3 店舗情報

- 電話番号は確認済みの番号を1つだけ主表示する。
- 住所は都道府県から記載する。
- 営業時間は曜日、昼、夜、ラストオーダーを読み分けられる形式にする。
- 臨時営業・休業は固定掲載せず、Instagramへ誘導する。

## 9. 素材要件

### 9.1 画像スロット

本書では最終使用画像をまだ確定しない。次工程で全候補を評価し、以下の役割へ割り当てる。写真は余ってよく、同一写真の使い回しを減らすため予備素材も保持する。

| Menu Highlights | 3〜5 | 代表料理の具体化 |
| Seasonal | 2〜3 | 季節・仕入れの変化 |
| Drinks | 2〜4 | ボトル、グラス、料理との組み合わせ |
| Course & Group | 1〜2 | 食卓・複数皿・グループ利用のイメージ |

| Lunch | 1〜2 | 昼営業の補足 |
| Access | 1〜2 | 現在の外観、暖簾、看板 |

### 9.2 素材ルール

- Instagram画面の矢印、カルーセルドット、投稿文、コメント、アカウント情報等のUIは最終公開画像に残さない。
- 可能であればスクリーンショットではなく元画像を支給してもらう。元画像がない場合は、既存画素を保つ範囲でUI除去・軽微な補正を行う。
- ロゴを自動トレースまたはAIで描き直さない。
- 料理、皿、酒瓶ラベル、暖簾文字、内装、家具を生成AIで作り替えない。
- 料理や店内が実物と異なって見える合成・過度な彩度・過度な広角補正を行わない。
- 色調補正はセクション間の統一感を目的とし、実物色を変えない。
- 最終配信用はWebPを基本とし、必要に応じてAVIFを追加する。HeroはDesktop / Mobileの専用cropを用意してよい。
- 元画像、編集マスター、公開用WebP、内部確認用スクリーンショットを別フォルダで管理する。

### 9.3 画像品質目安

- Hero Desktop: 長辺1600〜2000px程度。
- Hero Mobile: 長辺900〜1200px程度。
- 大型料理・店内: 長辺1400〜1800px程度。
- 補助写真: 長辺1000〜1400px程度。
- WebP品質は写真ごとに確認し、概ね82〜86を初期値とする。文字・ラベルがある酒瓶や暖簾は圧縮劣化をより厳しく確認する。
- `width` / `height`または`aspect-ratio`を実装側で必ず保持する。

- `noindex,nofollow`とサンプル表記。

### B 情報確認後に有効化

## 12. デザイン要件

詳細は「りんどう 営業用サンプルLP デザイン定義書」を正本とする。

- ビジュアルコンセプトは「余白に宿る、料理と美酒の夜」。炭火は確認済みの代表要素として補助的に扱い、店舗確認前に唯一のブランド核として固定しない。
- 生成り、紫黒、深緑、赤銅を基調とする。
- 見出しは明朝体、本文とUIは可読性の高いゴシック体。
- Hero、料理、店内では写真を主役にする。
- 同じカードや同じ左右分割を連続させない。
- 装飾ではなく、余白、写真比率、文字サイズ、背景色、情報量で変化を作る。
- 行政サイトのような青中心・均等配置・汎用カード中心の見た目にしない。

## 13. レスポンシブ要件

- 基準幅はMobile 375px、Tablet 768px、Desktop 1440px。
- 320px幅から横スクロールなく閲覧できる。
- HeroはDesktopの左右分割から、Mobileでは写真先行を基本とする。ただし初回画面内に店名・「西荻窪」・「お酒と料理」等の要点と主CTAの存在が分かるよう、写真の前後または安全な短いオーバーレイでブランド情報を先に認識できる構成にする。
- 写真の重なりや非対称配置はMobileで解除し、意味のあるDOM順にする。
- Menu Highlightsは2列以上を強制せず1列または2列で可読性を優先する。
- Course、First Visit、店舗情報の表・比較要素はMobileで縦型の説明リストへ変換する。
- CTAはMobileで全幅とし、主CTAを下部へ固定する。
- 200%ズーム時にも情報欠落・重なり・横スクロールを起こさない。

## 14. アクセシビリティ要件

- 通常文字と背景のコントラスト比は4.5:1以上。
- 意味を持つUI境界とアイコンは3:1以上。
- 主なタップ領域は44×44 CSS px以上。
- H1は1つ、見出し階層を飛ばさない。
- `header`, `nav`, `main`, `section`, `footer`, `address`を適切に使用する。
- すべての操作要素に見える`focus-visible`を設定する。
- 料理写真には簡潔で内容が分かるaltを付け、装飾写真は空altとする。
- 色やhoverだけで意味を伝えない。
- MobileメニューをキーボードとEscapeで操作できるようにする。
- `prefers-reduced-motion`へ対応する。

## 15. 技術要件

### 15.1 構成

- Next.js、React、TypeScript、CSSを使用する。
- 静的exportでGitHub Pagesへ公開する。
- サーバー処理、データベース、外部予約APIは使用しない。
- 店舗情報と外部リンクは1つの`siteData`へ集約し、代表料理は`menuHighlights`、コースは`courseData`、初回来店情報は`visitGuideData`等へ分離して更新箇所を限定する。
- 色、文字、余白、幅はCSS Custom Propertiesで管理する。
- Hero、CTA、店舗情報など再利用部分はReactコンポーネント化する。

### 15.2 GitHub Pages

- `output: 'export'`を前提とする。
- Project Pagesでは`basePath`を使用してサブパスを管理する。`assetPrefix`はCDN用途等の明確な必要がある場合を除き、サブパス対応目的では原則使用しない。
- 直接アクセスと再読込で404が発生しない1ページ構成にする。
- すべての画像・フォント・内部リンクがサブパス環境で解決されることを確認する。

### 15.3 SEO・公開制御

- `meta robots`へ`noindex,nofollow`を設定する。
- ページタイトルとdescriptionは営業用サンプルと分かる内容にする。
- sitemapの生成は不要。
- サンプルであることをFooterへ記載し、HeroまたはHero直下にも小さく「営業提案用サンプル」と表示して公式サイトとの誤認を避ける。

### 15.4 パフォーマンス

- 静的exportではNext.js標準のサーバー画像最適化に依存しない。画像は事前にAVIF/WebP等へ生成し、`<picture>` / `srcset`等で表示サイズに応じて配信する。`next/image`を使う場合は静的exportで成立する`unoptimized`または適切なカスタムloader構成を採用する。
- Hero以外の画像は遅延読み込みする。
- 画像の幅・高さまたはaspect-ratioを指定し、レイアウトシフトを防ぐ。
- Webフォントは必要なウェイトだけ読み込む。
- 不要なJavaScriptライブラリを追加しない。

## 16. QAと受入条件

### 16.1 表示確認

- 320px、375px、768px、1024px、1440pxでレイアウトを確認する。
- 横スクロール、文字切れ、画像の重要部分の欠落、要素の重なりがない。
- Header固定時とアンカー移動時に見出しが隠れない。
- Mobile固定CTAがFooter、ブラウザのセーフエリア、キーボードフォーカス中のリンクやボタンを隠さない。

### 16.2 操作確認

- 予約、Instagram、Googleマップ、電話の全リンクを確認する。
- Tabキーだけですべての操作要素へ到達できる。
- focus-visibleが背景に埋もれない。
- Mobileメニューを開閉でき、`aria-expanded` / `aria-controls`が状態と一致し、Escapeで閉じられる。閉じた後は開閉ボタンへフォーカスを戻し、閉じたメニュー内部へTab移動しない。
- reduced motion設定時に不要な動きが停止する。

### 16.3 コンテンツ確認

- 店名、住所、営業時間、定休日、電話番号、予約先が最新の確認内容と一致する。
- 12セクションが定義順に存在し、各セクションの役割が重複しすぎていない。
- Menu Highlightsの料理名・価格・Course条件は情報源と確認状態が明確で、未確認事項を断定していない。
- 中華そばをディナー主軸のHeroや主要ブランド訴求として掲載していない。
- First Visitの最低ドリンク、支払、子ども連れ等は確認済み項目だけを表示している。
- Instagram UIや第三者写真が掲載されていない。
- ロゴの縦横比、色、筆致が変更されていない。

### 16.4 技術確認

- `lint`と`build`が成功する。
- GitHub Pagesの公開URLで表示・リンク・画像を確認する。
- `noindex,nofollow`が出力HTMLに存在する。
- ブラウザコンソールにエラーがない。
- Lighthouseを参考にしつつ、キーボード、ズーム、実機相当幅を手動確認する。
