# りんどう 営業用サンプルLP デザイン定義書（12セクション・本実装品質想定）

更新日: 2026-09-28  
対象: 営業提案用サンプルLP / 12セクション / 本実装品質想定 / Mobile First  
後続工程: 使用画像選定・編集 → 12セクション調整 → Next.js / React / CSS実装

## 0. 前提・情報の扱い

### 0.1 この文書の正本

本書は、会話内で確定した「りんどう 営業用サンプルLP要件定義」と、ユーザー提供の店舗写真・ロゴを正本としてデザインへ展開する。デジタル庁デザインシステムは、視覚表現の模倣対象ではなく、アクセシビリティ、可読性、情報階層、UI状態、レスポンシブ設計の品質基準として参照する。

### 0.2 確定している要件

- 営業提案用サンプルとして公開するが、デザイン・情報設計・レスポンシブ・アクセシビリティは正式納品する本実装と同等の品質を想定する。
- コンテンツは12セクション + Global Header + Footerで構成し、4時間サンプル制約によるセクション削減は行わない。
- 最優先成果は「料理と酒の魅力を理解 → 店内・利用条件を確認 → 食べログ予約」までの導線を一貫させること。
- 主CTAは「食べログで予約」。Instagram、Googleマップ、電話は副導線として扱う。
- ディナーをブランドの主役としつつ、Lunchは独立セクションとして存在を明確にする。
- Food、Menu Highlights、Seasonal、Drinksを分離し、料理と酒の情報密度を高める。ただし同じ写真レイアウトを反復しない。
- Course & Group、First Visit、Accessでは感情訴求より情報精度・可読性を優先する。
- デザイン方向は「上質な和モダン」。料理、酒、空間、暖簾・筆文字ロゴを主なブランド資産とする。
- 添付済みの店舗写真とロゴは使用許可済み。最終使用画像は次工程で選定し、余剰素材は予備として保持する。

### 0.3 公開前に確認が必要な情報

- 食べログとInstagram投稿の間で、中華そばの提供店舗・現行ランチ内容に差がある。りんどうLPでは中華そばを主訴求に使用しない。
- 営業時間、定休日、電話番号、コース料金、予約条件、貸切人数、支払条件は、サンプル提出前に店舗確認する。
- 食べログには予約用番号 `050-5592-7511` と店舗番号 `080-5747-8820` が併記されている。確認完了までは電話を副CTAとして弱く扱う。
- 食べログの料理メニュー掲載更新日は2024年1月30日であり、代表料理名・価格は現行提供の確認が必要。価格を画像へ焼き込まず、HTMLテキストとして差し替え可能にする。
- 食べログのコースページには「お料理10品2時間飲み放題付パーティープラン 5,500円」等が掲載されているが、料金・品数・飲み放題時間・支払条件は正式公開前に店舗確認する。
- ロゴは正方形JPEGであり、透過版・ベクター版は未支給。勝手なトレース、変形、墨色の変更は行わない。

## 1. デザインコンセプト

### 1.1 ビジュアルコンセプト

**「余白に宿る、料理と美酒の夜」**

白木の静けさ、料理の温度、自然な酒の色、手書きロゴの揺らぎを、一つの画面内で対比させる。炭火は公開情報から確認できる代表要素として必要に応じて使うが、店舗確認前に唯一のブランド核として固定しない。情報を均等に並べるのではなく、静かな余白から大きな料理写真へ、暗い酒場の色面から明るい店内写真へと移る編集的なリズムを作る。

Heroでは「西荻窪の落ち着いた店」という安心感を伝え、Conceptで静かな導入を置く。その後、Food → Menu Highlights → Seasonal → Drinksで料理と酒への期待を段階的に高め、Course・Space・Lunch・First Visit・Accessで具体的な来店判断を支え、Final CTAで予約へ収束させる。長い1ページでも同じ密度・同じ構図を連続させず、感情訴求と情報整理を交互に置く。

### 1.2 与えたい印象

- 上質だが、格式張りすぎない。
- 料理人の手仕事と仕入れの季節感が伝わる。
- ナチュラルワイン、日本酒、料理が同居する自由さがある。炭火料理は確認済みの代表例として補助的に扱う。
- 清潔で落ち着きがあり、初めてでも予約しやすい。
- 個人店らしい温度と、信頼できる情報設計が両立している。

### 1.3 デザインキーワード

`墨` / `和紙` / `白木` / `料理の温度` / `余白` / `静かな熱` / `編集的` / `旬` / `夜の深さ`

### 1.4 店舗らしさの視覚化

- ロゴの墨のにじみを、色や飾りではなく「余白と不均一な構図」の根拠にする。
- 店内の白木と黒い床から、明るい生成りと深い紫黒の対比を抽出する。
- ワイン写真の橙・ロゼ色を、小さなアクセントとして使う。
- 料理写真は皿をカード内に閉じ込めず、画面外へ続くような大胆なトリミングで見せる。
- 罫線や装飾は細く、必要最小限とし、筆文字風の疑似装飾は追加しない。

## 2. デザイン原則

1. **料理とロゴに語らせる**  
   説明を増やす前に、写真のサイズ、余白、コピーの短さで魅力を伝える。ロゴ以外に筆文字フォントを多用しない。

2. **静と動を交互に置く**  
   コピー中心の静かなセクションと、写真が画面を占めるセクションを交互に配置する。同じカードグリッドを連続させない。

3. **予約判断に必要な情報は曖昧にしない**  
   営業時間、場所、予約先、価格注記は装飾より読みやすさを優先する。日々変わる情報はInstagramまたは食べログへ明確に誘導する。

4. **操作は一貫、表現は単調にしない**  
   CTAの文言・色・状態は統一しながら、セクションの構図、背景、写真比率、情報密度には変化をつける。

5. **アクセシビリティを視覚品質として扱う**  
   最小文字、コントラスト、フォーカス、タップ領域、見出し階層を仕上げの確認事項ではなく、初期設計に含める。

### 3.1 コントラスト方針

- `#201C2A` / `#F5F1E8`: 約14.8:1。
- `#6F2F2B` / `#FFFFFF`: 約9.9:1。
- `#3E5148` / `#F5F1E8`: 約7.5:1。
- `#5E5851` / `#F5F1E8`: 約6.2:1。
- 原則として通常文字も背景に対し4.5:1以上を確保する。
- `--color-copper`は和紙背景上の短いラベルや太字に限定する。小さい本文には使用しない。
- 写真上の文字は、写真自体の明暗に依存せず、グラデーションオーバーレイまたは不透明な面を介して4.5:1以上を確保する。

## 4. タイポグラフィ

### 4.1 フォントファミリー

- 日本語見出し: `Shippori Mincho`, `Yu Mincho`, `Hiragino Mincho ProN`, serif
- 日本語本文/UI: `Zen Kaku Gothic New`, `Hiragino Kaku Gothic ProN`, `Yu Gothic`, sans-serif
- 英字ラベル: `Cormorant Garamond`, Georgia, serif
- 数字・営業時間: 本文フォントを使用し、`font-variant-numeric: tabular-nums`を指定する。

明朝体はブランドの静けさを担い、ゴシック体は可読性と操作性を担う。英字フォントはセクションラベルに限定し、本文の日本語と競合させない。Webフォント読込失敗時もレイアウトが大きく崩れないフォールバックを設定する。

### 4.3 文字組みルール

- H1はDesktopで最大3行、Mobileで最大4行。語中で任意改行しない。
- 本文の可読幅は日本語で約32〜38文字、`max-width: 42rem`を目安とする。
- `<br>`による固定改行はHeroコピーなど限定箇所のみ。PC/Mobileで別の改行制御が必要な場合は表示切替用spanを用いる。
- 全文中央揃えにしない。中央揃えは短いコピーとCTAブロックだけに限定する。
- 縦書きは装飾ラベルまたは短いコピーだけに限定し、重要情報には使用しない。

## 5. レイアウト・グリッド

### 5.1 基本値

| 項目 | Desktop | Tablet | Mobile |
|---|---:|---:|---:|
| Viewport想定 | 1200px以上 | 768〜1199px | 767px以下 |
| 最大コンテンツ幅 | 1280px | `calc(100% - 64px)` | `calc(100% - 40px)` |
| 左右余白 | 48〜80px | 32px | 20px |
| グリッド | 12 columns | 8 columns | 4 columns |
| Gutter | 24px | 24px | 16px |
| セクション間 | 120〜168px | 96〜128px | 72〜104px |
| 小ブロック間 | 32〜56px | 28〜48px | 24〜40px |

### 5.2 ブレークポイント

- `sm`: 480px
- `md`: 768px
- `lg`: 1024px
- `xl`: 1280px

主な構造変化は768pxで行う。1024pxと1280pxは余白・文字・写真比率の調整に用い、デバイス名ではなくコンテンツの破綻点で判断する。

### 5.3 レイアウト原則

- HeroはDesktopで5:7の非対称分割、Mobileで写真とコピーを縦に再構成する。
- 文章と写真を毎回50:50にしない。7:5、4:8、全幅写真、狭い本文などを使い分ける。
- 情報整理セクションだけはグリッドを厳密に揃え、料理・ブランドセクションは1〜2カラム分のオフセットで編集的な余白を作る。
- 画面端まで伸びる写真と、最大幅内に収まる情報面を交互に使う。
- 12セクションを同じ高さにしない。Food / Drinks / Spaceは大きく、Menu Highlights / Lunch / First Visitは比較的コンパクトにしてページ長を制御する。
- `overflow-x: clip`に頼って不具合を隠さず、装飾要素を含めて横幅を制御する。

## 6. 写真・画像アートディレクション

### 6.1 素材の役割

最終使用画像は次工程で選定する。現時点では用途スロットだけを定義し、写真が余ることを許容する。

- Hero: 料理集合写真。Desktop / Mobileで別cropを用意してよい。
- Food: 料理の質感・温度を大きく見せられる写真2〜3枚。
- Menu Highlights: 食べログ掲載名と写真が整合する代表料理3〜5枚。
- Seasonal: 色・食材・皿の表情が異なる料理2〜3枚。固定メニュー一覧に見せない。
- Drinks: ナチュラルワインのボトル集合、グラスと料理、日本酒等。2〜4枚。
- Course & Group: 複数皿が並ぶ食卓、料理＋酒などの写真があれば1〜2枚。適切な素材がなければ写真なしでも成立させる。
- Space: 店内広角、窓側、夜、テーブル近景から3〜4枚。
- Lunch: 昼料理1〜2枚。ディナーのHeroと競合しない。
- Access: 現在の外観、暖簾、看板から1〜2枚。
- Final CTA: 原則写真なしでも成立。使用する場合は既出写真の再利用を1枚まで許可する。
- Logo: 正式JPEGをHeader / Hero / Footerで使用。暖簾の実写ロゴはBrand / Accessの補助素材として扱える。

Instagram UI、カルーセル矢印、ドット、投稿文、コメント、アカウント情報が写った状態では掲載しない。可能な限り元写真を使用し、スクリーンショットしかない場合は料理・瓶・暖簾文字・内装を変えない範囲でUIを除去する。

### 6.2 トリミングと比率

| 用途 | Desktop | Mobile | 基本object-position |
|---|---|---|---|
| Hero料理 | 4:5〜5:6 | 4:5 | 料理中央、主皿を切らない |
| Food主写真 | 4:3〜3:2 | 4:5 | 料理の主役を中央〜やや外側へ |
| Menu Highlight | 4:3 / 1:1混在可 | 4:5 / 1:1 | 皿の特徴が分かる位置 |
| Seasonal | 3:2 / 16:9 | 4:5 | 余白を残し編集的に |
| 酒ボトル | 16:9または2:1 | 3:2 | ラベルと瓶口を可能な限り残す |
| グラス＋料理 | 4:5 / 3:4 | 4:5 | グラスと料理の両方を残す |
| 店内広角 | 16:9 | 4:3 | 窓と奥行きの消失点を維持 |
| 店内近景 | 3:4 | 4:5 | 椅子とテーブル面を主役にする |
| 外観 | 16:9〜3:2 | 4:5 | 暖簾・入口・看板が分かる |
| ロゴ | 1:1固定 | 1:1固定 | `center center`, `contain` |

### 6.3 画像処理

- 明るさ: 元画像基準で `+2〜+6%`。白木が白飛びする場合は上げない。
- 彩度: `-4〜0%`。料理の色を不自然に鮮やかにしない。
- コントラスト: `+4〜+8%`。暗部を潰さず、炭火料理の立体感を出す。
- 色温度: 店内写真の青被りを弱め、白木が自然に見える程度に暖色へ調整する。
- 粒子・和紙テクスチャを写真全体に後付けしない。
- 同一セクションの写真は色温度を揃えるが、料理の実物色を変える加工はしない。
- スクリーンショット由来素材の高画質化は、既存の料理・皿・瓶ラベル・暖簾文字・家具形状を変えない範囲に限定する。生成補完で見た目を作り直さない。
- Instagramの矢印・ドット等は最終画像から除去する。UI除去後の背景補完は木目や壁など単純背景に限定し、料理そのものへ補完をかけない。
- AVIF/WebPを優先し、表示サイズの1.5〜2倍程度のsrcsetを用意する。

### 6.4 写真と文字

- 長文を写真へ直接重ねない。
- Heroで文字を写真に重ねる場合も、画面の20〜30%程度のグラデーション面を介し、可読性を写真の状態に依存させない。
- 料理名や説明は写真外に置く。短い英字ラベルのみ写真上への配置を許可する。
- Mobileでは写真上の文字を原則分離し、写真→コピーの順にする。

### 6.5 ロゴ使用

- ヘッダーでは48〜56px角で全体を表示し、横にテキストの店名を添える。ロゴ単体を読ませる設計にしない。
- HeroではDesktop 160〜220px角を上限目安とする。Mobileでは96〜136px程度まで縮小を許容し、初回画面内の店名・地域・業態・CTAを圧迫しない。
- 角丸マスク、円形切抜き、ドロップシャドウ、色変更、反転、縦横比変更を禁止する。
- 背景とロゴ画像の紙色差が目立つ場合は、画像周囲を同系色の面として扱い、境界を無理に消さない。

## 7. UIコンポーネント

### 7.1 Header

- 高さ: Desktop 80px、Mobile 64px。
- 初期状態: Hero上では半透明の和紙色。スクロール後は `rgba(245,241,232,.94)` と `backdrop-filter: blur(12px)`。
- Desktop: 左にロゴ＋店名、中央〜右にアンカーリンク、右端に予約CTA。
- Mobile: 左にロゴ＋店名、右にメニューボタン。予約CTAは画面下部の固定バーへ移す。
- 固定時は1pxの柔らかい境界線を表示する。大きな影は使わない。

### 7.2 Navigation

- ラベルは主要5〜6項目へ絞る。推奨: 「りんどうについて」「料理」「お酒」「店内」「初めての方へ」「店舗情報」。12セクションをすべてHeaderへ並べない。
- 通常: 紫黒。hover: 下線が左から右へ伸びる。active: 赤銅色の短い下線。
- 現在位置は色だけに頼らず、下線または`aria-current="location"`で示す。
- Mobileメニューは画面右からの細いドロワーではなく、全面に近い和紙色のパネル。項目間を56px以上確保する。開閉ボタンは`aria-expanded` / `aria-controls`を持ち、閉じた後は開閉ボタンへフォーカスを戻す。

### 7.3 Button / CTA

**Primary: 食べログで予約**

- 高さ56px、Mobileは最小52px。左右padding 28px。
- 背景 `#6F2F2B`、文字 `#FFFFFF`、角丸2px。丸薬型にはしない。
- hover: `#572420`、1px上へ移動。
- active: `#431A18`、移動を戻す。
- focus-visible: 2px紫黒 + 4px黄色の二重リング。
- 外部遷移アイコンを末尾に置き、装飾アイコンは`aria-hidden="true"`。

**Secondary: Instagramで最新情報を見る / 電話する**

- 透明背景、1px `#201C2A`、文字 `#201C2A`。
- hover: `#E8DED0`、下線を追加。
- 電話番号が未確認の間は本文内リンクに留め、HeroのCTAにはしない。

### 7.4 Card

- 汎用カードを乱用しない。
- 使用箇所はコース概要、店舗情報の補助情報など、内容が独立して比較される箇所に限定する。
- 角丸0〜4px、影なし、罫線または背景差で面を分ける。
- カード全体をリンクにする場合、内部に別リンクやボタンを入れない。

### 7.5 Link

- 本文リンクは下線を常時表示。hoverで下線太さを1pxから2pxへ変更。
- リンク文言は遷移先を具体的にする。「こちら」だけにしない。
- visitedは本文導線では識別可能な深い紫 `#5A365E` を使用してよい。主要CTAは訪問済みでも外観を変えない。

### 7.6 First Visit / Disclosure

- First Visitは独立した情報セクションとして実装する。
- 基本は`dl`と罫線で整理し、説明が長い項目だけネイティブの`details` / `summary`を使用する。
- 質問・見出し全体を44px以上の操作領域にする。
- 開閉アイコンは45度回転。カード影やFAQ SaaS風UIは使わない。
- 画面表示する条件は店舗確認済み情報に限定する。

### 7.7 Access

- `address`要素を用い、住所、駅からの徒歩分数、営業時間、定休日を`dl`で整理する。
- 地図画像を埋め込むより、「Google マップで開く」の明確な外部リンクを設ける。
- 営業時間は曜日と昼夜を視線で追える2列構成。Mobileではラベルと値を上下にする。

### 7.8 Reservation / Contact

- 最終CTAは濃色背景の独立セクションとし、ページ内で最も高いコントラストを持たせる。
- 「ディナーの席を予約する」→食べログ、「当日の営業を見る」→Instagramの順に配置する。
- Mobile固定CTAは安全領域を含め高さ72〜80px。コンテンツ末尾に同等のpaddingを確保する。

### 7.9 Footer

- 紫黒背景。ロゴ、店名、住所、Instagram、食べログ、サンプル表記を配置する。
- ナビゲーションを再掲しすぎず、必要な外部導線と著作権表記だけに絞る。
- 「営業提案用サンプル」の表記はCaptionサイズでもコントラスト4.5:1以上を確保する。

## 8. セクション別アートディレクション

### 8.0 Global Header / Navigation

- **目的:** 店名の認知、主要情報への移動、予約への常時導線。
- **構図:** Heroの余白へ重なる水平バー。ロゴは小さく、予約CTAだけを強くする。
- **Desktop Navigation:** 「りんどうについて / 料理 / お酒 / 店内 / 初めての方へ / 店舗情報」程度に絞る。
- **Mobile:** ハンバーガーと下部固定予約CTAへ分離。12セクションすべてをHeaderへ露出しない。

### 8.1 Section 01 — Hero

- **目的:** 初回画面で「りんどう・西荻窪・お酒と料理・予約導線」の要点が分かる状態を作る。
- **Desktop:** 左5カラムを和紙背景のコピー面、右7カラムを料理集合写真。写真を40〜64px程度ずらし、単純な50:50にしない。
- **テキスト:** `NISHIOGIKUBO / DINING & SAKE`、H1「西荻窪、お酒と料理を楽しむ夜。」、短いリード、予約CTA。
- **Mobile:** 写真だけで初回画面を占有しない。「りんどう / 西荻窪 / お酒と料理」を先に認識できる構成。H1は40〜44px基準。
- **写真:** 最も情報量の高い料理集合。Desktop / Mobileで別crop。

### 8.2 Section 02 — Concept / りんどうについて

- **目的:** 写真の勢いから一度静かな呼吸へ戻し、店の立ち位置を短く言語化する。
- **Desktop:** 12カラム中、本文5〜6カラム。余白を広く取り、暖簾やロゴ実写を小さく添えることは可。
- **背景:** `--color-washi`。
- **テキスト:** H2 + 100〜160文字程度。未確認ストーリーを書かない。

### 8.3 Section 03 — Food / 料理

- **目的:** ページ前半で最も強い料理体験を作る。
- **Desktop:** 大型写真8カラム + 本文4カラム、または全幅写真 + 狭い本文。料理写真をカードへ閉じ込めない。
- **背景:** 生成り〜白。皿の色を生かす。
- **コピー:** 「料理を楽しむ。」程度の短いH2。炭焼き・魚・一品などを代表カテゴリとして補足。
- **Mobile:** 写真 → 見出し → 短文。大写真1枚を最優先。

### 8.4 Section 04 — Menu Highlights / 代表料理

- **目的:** 具体的な料理名を3〜5品見せ、Foodの抽象的な魅力を予約判断へ近づける。
- **Desktop:** 均等4カード禁止。大1 + 小2〜4の非対称グリッド、または縦方向のEditorial list。
- **料理名:** HTMLテキスト。価格は確認済みの場合のみ。
- **背景:** `--color-surface`または`--color-washi`。Foodより情報整理を強める。
- **注記:** 「内容は仕入れ等により変わります」。
- **Mobile:** 1列を基本に、1:1と4:5を混在させすぎない。

### 8.5 Section 05 — Seasonal / 仕入れで変わる一皿

- **目的:** 固定メニュー一覧とは異なる「その時の一皿」の期待を作る。
- **Desktop:** 横長写真を画面端まで伸ばし、別の料理ディテールを小さくオフセット。文章量は少なくする。
- **背景:** `--color-sand`または写真の余白。
- **CTA:** 「今日の内容はInstagramで見る」。
- **禁止:** 産地・生産者・入荷頻度の創作。

### 8.6 Section 06 — Drinks / 酒

- **目的:** ページの空気を夜へ切り替え、酒を独立した来店動機として見せる。
- **背景:** `--color-ink`または`--color-moss`。ページ中盤の最も深い色面。
- **Desktop:** 横長ボトル集合を大きく置き、グラス＋料理の縦写真を1枚組み合わせる。2枚で十分なら増やさない。
- **テキスト:** `WINE / SAKE`等の英字ラベルと短文。銘柄一覧は固定しない。
- **CTA:** 食べログまたはInstagramへのSecondary導線。

### 8.7 Section 07 — Course & Group

- **目的:** 会食・グループ・貸切の判断材料を整理する。
- **背景:** `--color-sand`。
- **Desktop:** 左に大きな`COURSE`ラベル、右にコース概要を罫線リスト。写真は1枚まで、適切な素材がなければ写真なしで成立させる。
- **表示項目:** コース名、料金、品数、時間、飲み放題、貸切相談等。確認済み項目のみ。
- **CTA:** 「コース・空席を食べログで確認する」。

### 8.8 Section 08 — Space / 店内・利用シーン

- **目的:** 料理と酒の期待を、実際に過ごす場所へ接続する。
- **Desktop:** 店内広角を16:9で大きく使用。補助写真1〜2枚を非対称に配置。昼・夜の色温度差は自然に整える。
- **背景:** 明るい生成りへ戻し、Drinks / Courseの濃色から開放感を作る。
- **テキスト:** 「料理と酒に、ゆっくり向き合う。」等の短いコピー。
- **Mobile:** 重なりを解除し、広角 → 短文 → 近景。

### 8.9 Section 09 — Lunch / 昼のりんどう

- **目的:** ディナー主軸を崩さず、昼営業という別の来店入口を明確にする。
- **構図:** 本実装では単なる横帯ではなく、料理写真1〜2枚 + 営業時間 + 最新情報導線の中規模セクション。
- **背景:** `--color-surface`。夜セクションとの差を明確にする。
- **注意:** 中華そばを主ビジュアルに固定せず、現行メニュー確認後に採用判断する。

### 8.10 Section 10 — First Visit / 初めての方へ

- **目的:** 予約前の不安と認識違いを減らす。
- **構図:** ページ内で最も規則的な情報UIの一つ。2列`dl`または罫線リスト。説明が長い項目だけ`details/summary`。
- **内容候補:** 予約、最低ドリンク、支払方法、ランチ予約、禁煙、子ども連れ、貸切等。確認済み情報のみ表示。
- **背景:** `--color-washi`。カード影を使わない。

### 8.11 Section 11 — Access / 店舗情報・アクセス

- **目的:** 来店直前の事実確認を最短で行えるようにする。
- **Desktop:** 左6〜7カラムに住所・営業時間・定休日等、右5〜6カラムに現在の外観写真。外観の暖簾・入口・看板が分かるcropを使う。
- **CTA:** 「Google マップで開く」「食べログで店舗情報を見る」。
- **背景:** `--color-surface`または`--color-washi`。
- **禁止:** 架空の地図、未確認の道順画像。

### 8.12 Section 12 — Final Reservation CTA

- **目的:** 長いページの情報を予約という一つの行動へ収束させる。
- **背景:** `--color-ink`。写真なしでも成立させる。
- **Desktop:** 左にH2、右にPrimary CTA。予約方法を増やしすぎない。
- **CTA:** 食べログ予約をPrimary、InstagramをSecondary。電話は確認済みの場合のみ補助リンク。
- **Mobile:** コピー → Primary → Secondary。固定CTAと重複しても完結点として残す。

### 8.13 Footer

- **背景:** Final CTAと同じ濃色を継続。
- **内容:** ロゴ、店名、住所、Instagram、食べログ、営業提案用サンプル表記、著作権表記。
- **方針:** Navigationを大量に再掲しない。

## 9. モーション

- 基本継続時間: 180〜320ms。写真Revealのみ最大600ms。
- Easing: `cubic-bezier(.22, 1, .36, 1)`。
- Scroll Reveal: `opacity: 0 → 1` と `translateY(16px → 0)`。セクション全体ではなく見出し・写真単位で1回だけ実行する。
- 写真: hover可能端末に限り、5〜8秒相当の緩やかな`scale(1 → 1.025)`をhover時だけ行う。自動ズームはしない。
- Button: 150〜180msで背景色と1px移動。大きな跳ねや発光は禁止。
- Header: 200msで背景・境界線・高さを切り替える。
- Mobile Menu: 240msのopacityと8px程度の移動。大きな横スライドで酔いを誘発しない。
- `prefers-reduced-motion: reduce`では、Reveal、transform、smooth scrollを無効化し、状態変化は即時またはopacityのみとする。

## 10. レスポンシブ方針

- PC版の縮小ではなく、12セクションそれぞれを重要度順に再編集する。
- Mobileでは写真を主役にしつつ、情報密度が高いMenu Highlights / Course / First Visit / Accessは可読性を優先する。
- HeroはDesktop左右分割からMobile写真先行へ変更するが、写真だけで初回画面を占有しない。
- Conceptは小写真を省略してよい。Foodは大写真1枚を最優先し、補助写真を削ってもよい。
- Menu HighlightsはDesktopの非対称グリッドをMobileで1列化する。横スクロール必須にしない。
- Seasonalのオフセット・重なりはMobileで解除する。
- Drinksは暗背景を維持し、ボトル集合 → 短文 → グラス写真の順にする。
- CourseとFirst Visitは横表を使わず、縦型`dl`または`details/summary`へ変換する。
- Spaceの写真重なりを解除し、意味のある閲覧順にDOMを構成する。
- Lunchはディナーセクションよりコンパクトにし、写真2枚を無理に並べない。
- Accessは外観写真 → 住所・営業時間 → Map CTAの順を基本とする。
- Navigationは主要項目だけメニューへ格納し、予約CTAのみ下部固定する。
- Mobile固定CTAによって本文・Footerが隠れないよう、`env(safe-area-inset-bottom)`と末尾余白を加える。
- 320px幅、200%ズーム、長い日本語文字列でも横スクロールを発生させない。
- タッチ端末ではhover依存の情報開示をしない。

## 11. アクセシビリティ・実装ルール

### 11.1 文書構造

- `header`, `nav`, `main`, `section`, `footer`, `address`を意味に沿って使用する。
- H1は1ページに1つ。主要セクションをH2、内部項目をH3とし、見た目のために階層を飛ばさない。
- 各sectionは見出しを持たせ、必要に応じて`aria-labelledby`で関連付ける。
- ナビゲーションのアンカー移動先には`scroll-margin-top`を設定する。

### 11.2 操作性

- ボタンは最低44×44 CSS px。本文リンクも最低24×24px相当、独立CTAは44px以上を確保する。
- すべての操作要素にキーボードフォーカスを表示する。`outline: none`のみの指定は禁止。
- focus-visibleは黒2pxと黄色4pxの二重リングを基本とし、背景色を問わず識別可能にする。
- メニュー開閉時はフォーカスを適切に移動し、開閉ボタンへ`aria-expanded` / `aria-controls`を設定する。Escapeで閉じ、閉じた後は開閉ボタンへフォーカスを戻す。閉じたメニュー内へTab移動させない。
- 外部リンクは新規タブで開く場合、その旨を視覚・支援技術の双方へ伝え、`rel="noopener noreferrer"`を付ける。

### 11.3 色・文字

- 通常文字は背景に対して4.5:1以上、意味を持つUI境界やアイコンは3:1以上を確保する。
- 色だけで現在位置、リンク、エラー、選択状態を伝えない。
- Bodyは16px未満にしない。Captionの13pxは補助情報に限定する。
- テキストの200%拡大時にも欠落、重なり、横スクロールを起こさない。

### 11.4 画像

- 料理写真のaltは、画面上のキャプションと重複しない範囲で被写体を簡潔に説明する。
- 雰囲気だけの装飾写真は`alt=""`とする。
- ロゴaltは「りんどう」。隣接して同じ店名テキストがある場合は空altとする。
- CSS背景に意味のある情報を持たせない。

### 11.5 Next.js / React実装

- CSS Custom Propertiesで本書の色、余白、タイポグラフィをトークン化する。
- 営業時間・住所・外部リンクは`siteData`、代表料理は`menuHighlights`、Courseは`courseData`、First Visitは`visitGuideData`など、更新頻度と責任範囲ごとにデータを分離する。コンポーネント内へ値を散在させない。
- 静的exportではNext.js標準のサーバー画像最適化に依存せず、事前生成したAVIF/WebPと`<picture>` / `srcset`を基本とする。`next/image`を使う場合は`unoptimized`または静的exportで成立するカスタムloader構成にする。
- 予約CTAは共通コンポーネント化し、Hero、Header、最終CTAで文言とリンク先を統一する。
- Next.jsは静的exportを前提とし、Project Pagesでは`basePath`を使用してサブパスを管理する。`assetPrefix`はCDN等の明確な必要がある場合を除き、サブパス対応目的では原則使用しない。
- 外部通信を伴う予約APIやフォームは実装しない。
- `meta robots="noindex,nofollow"`を設定し、Hero付近とFooterに「営業提案用サンプル」を表示する。OG画像・title/descriptionも公式サイトではないことが分かる管理にする。
- Lighthouseだけに依存せず、キーボード操作、実機相当幅、200%ズーム、reduced motionを手動確認する。

## 12. NGデザイン

- デジタル庁サイトの青、白、均等カード、行政文書的な見た目をそのまま流用する。
- すべてのセクションを「中央見出し＋3カード＋ボタン」で構成する。
- 全写真を同じ角丸カードへ閉じ込める、または全要素へ大きな角丸と影を付ける。
- 和風を示すために、筆文字フォント、麻の葉、金箔、赤い判子などを追加する。
- ロゴを円形に切り抜く、横長に変形する、白黒反転する、背景を自動削除して筆致を損なう。
- 写真へ長文を重ね、暗いオーバーレイで料理の色を失わせる。
- 料理写真の彩度を過度に上げる、AIで皿や料理を補完する、実物と異なる演出をする。
- 価格・営業時間・電話番号など未確認情報をデザイン上の都合で断定する。
- 中華そばをHeroや主要セクションで訴求する。店舗確認前に「炭火」をHeroの唯一のブランド核として固定する。
- InstagramのスクリーンショットをUIごと掲載する。
- 予約、Instagram、電話を同じ強さで並べ、主行動を曖昧にする。
- hoverでしか読めない情報、横スクロール必須のMobileレイアウト、自動再生動画、過度なパララックスを使う。
- 細すぎる明朝体、小さな薄色文字、写真に依存した低コントラスト表現を使う。

## 13. このLPで最も重要なデザイン上の判断

1. **12セクションを増やしても、情報量を均等にしない。** Food / Drinks / Spaceを視覚的ピーク、Menu Highlights / Lunch / First Visit / Accessを情報整理の谷として設計し、長さを感じにくいリズムを作る。
2. **「料理」と「酒」を分離し、それぞれを独立した来店動機として見せる。** ただし同じカードグリッドは反復しない。
3. **Foodは感情、Menu Highlightsは具体性、Seasonalは変化を担当させる。** 3セクションの役割を混同しない。
4. **ロゴ・暖簾・白木・紫黒・生成りを設計言語へ翻訳し、和風装飾を追加しない。**
5. **Course / First Visit / Accessでは装飾より事実の読みやすさを優先する。** 未確認情報は美しい仮データで埋めない。
6. **写真は多く使ってよいが、1写真1役割を基本とする。** 同じ料理写真の反復を避け、余剰素材は予備として保持する。
7. **料理・酒・内装の編集で生成AI感を出さない。** UI除去、高画質化、色調整、cropは行うが、料理・皿・ラベル・暖簾・家具を生成で変えない。
8. **正式サイト時の主行動としてディナー予約を一貫して示しつつ、GitHub Pages版は営業デモであることを明示する。**
9. **アクセシビリティはデザイン品質として扱う。** 4.5:1以上の文字コントラスト、44px以上の主要操作領域、明確なフォーカス、意味のあるHTML、200%ズームを前提にする。
